# Deployment example: Render + PostgreSQL

> Portfolio example only. This file documents an intended deployment shape; it
> is not a claim that this repository currently has a live public instance.

The repository includes [`render.yaml`](../render.yaml) as a reproducible
blueprint for the following small, free-tier setup:

```text
Render Free (Docker web service)
        |
        | TLS JDBC connection
        v
Neon Free PostgreSQL project (intended PostgreSQL 16)
```

## What the example configures

- Render starts the Docker image with `prod,demo` and checks
  `/actuator/health` before considering the service ready.
- Swagger is enabled only because the `demo` profile is explicit. Plain
  `prod` keeps Swagger and OpenAPI disabled.
- Neon supplies PostgreSQL externally. The application still runs Flyway
  migrations and Hibernate in `validate` mode; the cloud platform does not
  manage the schema for it.
- `JWT_SECRET` is generated by Render. Database credentials and the JDBC URL
  are entered in Render as external values and are never committed.
- `autoDeployTrigger: checksPass` means a Render deploy is allowed only after
  the repository checks pass.

## Values entered outside Git

Use the provider's JDBC connection value and keep TLS enabled. The following
is a shape example, not a working credential:

```text
SPRING_PROFILES_ACTIVE=prod,demo
JDBC_DATABASE_URL=jdbc:postgresql://<neon-host>/<database>?sslmode=require
DB_USER=<neon-role>
DB_PASSWORD=<entered-in-render-only>
JWT_SECRET=<render-generates-this>
JWT_ISSUER=task-manager-api-demo
JWT_AUDIENCE=task-manager-api-demo-users
CORS_ALLOWED_ORIGINS=https://<actual-render-service>.onrender.com
SPRING_DATASOURCE_HIKARI_MAXIMUM_POOL_SIZE=3
SPRING_DATASOURCE_HIKARI_MINIMUM_IDLE=1
RATE_LIMIT_TRUST_FORWARDED_FOR=true
```

If the generated Render hostname differs from the example in `render.yaml`,
update `CORS_ALLOWED_ORIGINS` to the actual hostname before testing Swagger.

## Manual verification after an actual deploy

This example becomes evidence only after someone with access to Render and
the database provider performs and records these checks:

1. Wait for `/actuator/health` to return `200` and confirm Flyway completes.
2. Open `/swagger-ui.html`; use disposable test credentials only.
3. Run register, login, project, task, status transition, refresh, replay
   rejection, logout, audit, and health checks.
4. Let the free service sleep, then repeat health and Swagger to observe the
   cold start.

Render Free may suspend an idle service and the first request can take about a
minute. No keep-alive job is used to hide that platform behavior.
